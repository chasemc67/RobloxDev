## How the places were made
- Asset Manager in this Studio has no "Add New Place" (Codex looked: logs/stages/z-places.log). Instead, each course place was made from a copy of playtest-v241.rbxl, opened as a local file and stripped (below). Codex then ran File > Publish to Roblox As > VR Mini Golf > new place, and renamed the default "MetavrseBuilder's Place: 10122026_1" in Creator Hub.
- **Lantern Grove place**: workspace.Lobby, CourseSugarloaf and ServerStorage.LobbyLibrary / SugarloafMovers deleted. Sugarloaf's terrain box was cleared (FillBlock Air, 256-stud chunks). SpawnLocation is back on the Welcome Plaza (WorldLayout.spawn, (206, 24.1, 214), as CourseBuilder places it when there's no lobby). Lighting, World, Course and Baseplate are unchanged.
- **Sugarloaf Canyon place**: workspace.Lobby, Course, World and Baseplate deleted, plus ServerStorage.LobbyLibrary / LanternGroveWorld / LanternGroveProps. Lantern Grove's terrain was cleared (512-stud chunks over the WorldLayout bounds). SpawnLocation is beside the H1 tee (tee + (7, 0, 3), on the terrain at y 18). The Sugarloaf scenery kit was **not** imported (rework in progress).
- **Lobby**: Course, CourseSugarloaf, World and Baseplate deleted, Terrain cleared (the lobby has no terrain), and the course libraries removed from ServerStorage. Lobby dressing and portal meshes were left for phase 2.
- Each place stores its role in the workspace attribute **PlaceRole** (lobby | lantern_grove | sugarloaf_canyon). `ReplicatedStorage.Golf.Places` maps roles to place IDs; game.PlaceId is the fallback.

## Sync method (shared scripts)
All three places run **the same scripts**, and `games/vr-mini-golf/src` is the source of truth. For each place: open only that place, run `python3 tools/run_playtests.py push $(find src -name '*.luau')` (the runner now uses the only open Studio, or `GOLF_STUDIO=<name substring>`), run `smoke`, then Save + Publish, close, and move to the next place. After the final push, `run_playtests.py export` matched src/ byte for byte in all three places. The place content differs per place; the scripts don't. Documented in places.json "sync".

## Code (all places)
- **Places** (new, ReplicatedStorage.Golf): role(), isLobby(), course(), placeIdOf().
- **PlaceTeleport** (new, ServerScriptService): `TeleportAsync(placeId, {player}, TeleportOptions)` with teleport data {from, dest, reason}. 4 s cooldown per player, 2 retries (and TeleportInitFailed Flooded/Failure retry). It fires `Remotes.TeleportStatus` "start" to the client first. **Studio skips the teleport**: it prints it, sets workspace attribute `LastTeleportRequest = "<player>|<dest>|<reason>|<placeId>"`, then fires "skipped". Remote `RequestTeleport(dest)` handles the course cards and Back to Lobby.
- **TeleportScreen** (new client module): the loading screen (Config.UI.LoadingLanternGrove / LoadingSugarloaf, or the title art for the lobby) goes up locally and is handed to `TeleportService:SetTeleportGui`. "skipped" or "failed" takes it down and shows a toast; it also times out after 30 s. **ReplicatedFirst.ArrivalScreen** (new) keeps the arriving teleport GUI up until the new place has loaded, then fades it.
- **GolfServer**: returns immediately in the lobby. In a course place it hosts only that course (`PLACE_COURSE`). A join starts hole 1 on Ready; the lobby-parking code from stage x is gone. Picking the other course on the course card teleports there. A finished round shows results and teleports to the lobby after `Config.ReturnToLobbyAfter` (30 s) unless the player chooses Play again; this is skipped in the harness (GolfTestMode). Counted rounds write the leaderboard. ExploreData and its walls are built only in Lantern Grove. A Studio-only `GolfFinishDebug` hook (normal playtests only) drives the finish > lobby test.
- **LobbyServer** (new; returns immediately in course places): loads and saves settings and personal bests (so the cards show "Best"), and back-fills each joining player's saved personal bests into the leaderboard stores. It handles **portal triggers** (`Lobby.Portals.Portal_<course>`: 10x10x3 Neon sheets at transparency 0.72 inside the LG and SC arches; the HumanoidRootPart touching one calls PlaceTeleport) and the **leaderboard wall** (refresh every 60 s, names via UserService).
- **Leaderboard** (new): OrderedDataStore `VRMiniGolf_Best_v1_<courseId>`, key UserId, value = best total. `UpdateAsync` keeps the lower value. `GetSortedAsync(true, 8)`. Studio stays offline like PersonalBest (Studio API access is off) unless PBInStudio is set; offline, `top()` reads workspace attribute `LeaderboardMock` for tests.
- **LobbyBuilder**: `BuildPortals()` and `BuildLeaderboard()` (an invisible part flush with the lobby side of leaderboard_wall, carrying a SurfaceGui "Best Rounds" with one column per course and 8 rows each). Build() calls both.
- **GolfMain**: the lobby branch has no BallController, HUD, golf controls or VRControls. It runs LobbyRoam (walk; VR players use Roblox's own VR camera, walking and UI pointer), the FrontEnd and the TeleportScreen.
- **FrontEnd**: in the lobby (`Places.isLobby()`) the course cards teleport, and the hole and par counts come from Config when the course isn't built in the place. Course places start with the menu closed. The title has a "Lobby" button; the results page has "Back to lobby" plus a "Back to the lobby in N s" countdown. Art: menu_frame.png as a 9-slice frame (SliceCenter 64,64,1136,736, SliceScale 0.5) over the title art, close_x.png as the X, and menu_button.png with a "Menu" label. **The Menu button is now top right**: its ScreenGui uses `ScreenInsets.TopbarSafeInsets`, anchored to the right edge of the free top-bar area. With `ScreenInsets.None`, an early version landed 62 px short of the right edge on the iPhone; that was fixed before the final publishes.
- **HUD**: the Menu button in the right-hand column is removed, so the top-right Menu button is the only one in both lobby and course places.
- **Courses/Config**: Courses.DEFAULT is this place's course. `playable` = built here **or** has a place. The Config courses have holes and par (LG 9 / 27, SC 18 / 54) and their loading art; `ReturnToLobbyAfter = 30`.

## Art
- **The box's /workspace wasn't reachable from the Mini** (no `box` host; grokbot on Tailscale refuses ssh), so `assets/vr-mini-golf/ui/menu/{menu_frame,close_x,menu_button}.png` and `ui/loading/loading_{lantern_grove,sugarloaf_canyon}.png` are **stand-ins** made by `ui/_make_standins.py`. They use the same names and sizes as the brief, the 9-slice margins match SliceCenter 64,64,1136,736, and the loading screens use the course card art on the blurred title background. They were uploaded with MCP upload_image; the IDs are in tools/stage_z_assets.json and Config.UI, and all five returned PreloadAsync Success. To swap in the real art: replace the PNGs, upload them, update Config.UI, and push + publish all three places.
