## Export settings

- Blender 4.5.9 LTS, scene unit system **NONE**, so 1 Blender unit = 1 stud. Modelled Z-up.
- FBX: `axis_forward='-Z'`, `axis_up='Y'`, `apply_scale_options='FBX_SCALE_UNITS'`, global scale 1.0, `mesh_smooth_type='FACE'`, no leaf bones, no animation, `path_mode='COPY'` + `embed_textures=True` (the PNGs are inside each FBX).
- Axis mapping: Blender (x, y, z) -> Roblox (x, z, -y): Blender +Y = Roblox -Z (north). So the props come into Roblox upright, at true stud size, and in the same orientation as the holes.json local frame (-Z = north = play direction).
- Look: one mesh per material, so each becomes its own MeshPart. Textured materials (wood, bark, stone, moss, foliage, felt, ...) carry a Principled BSDF image texture plus box-projected UVs; the rest are flat colours. Every material also has a flat base colour, so the props still read correctly if textures are skipped (fallback table below).

## Import instructions for RobloxDevBot

1. **Import**: in Studio use File > Import 3D (or Open Cloud asset upload) on `fbx/<prop>.fbx`. Keep the hierarchy, so you get one Model per prop with one MeshPart per material. **Set the scale unit to Stud** (the FBX header says metres, but the values are studs; see 'Import scale note'). Check that lantern_large comes in 2 studs tall. If the importer offers a 'world forward/up' option, use Y up / -Z forward.
2. **Materials**: for each MeshPart named `<prop>__<Material>` (an optional `_tag` suffix is the same material), set `Color`, `Material` and `Transparency` from the material table below (also in `manifest.json > parts`). Neon parts (`Glow`, `Firefly`, `ShroomGlow`) are the light sources: parent a PointLight to each Glow part (Range 8, Brightness 0.6 day / 1.6 night, Color #FFB347). Paper can take Transparency 0.15 at night so the Neon core shows through.
3. **Physics**: on every MeshPart set `Anchored=true`, `CanCollide=false`, `CanTouch=false`, `CanQuery=false`, `CastShadow=true` (false on Neon/Water/Foam), `CollisionFidelity=Box`, `RenderFidelity=Automatic`.
4. **Pivot**: every child mesh shares the prop origin (base centre for static props, the stated pivot for moving parts). A MeshPart's Position is its own bbox centre, so for each part the FBX origin is at `part.CFrame * CFrame.new(-Vector3.new(table.unpack(parts[i].bbox_center_from_origin)))` (manifest, Roblox axes). If the importer did not keep the pivot, set each `part.PivotOffset = CFrame.new(-c)` with that `c`, and `Model.WorldPivot` = the same point. Then place with `Model:PivotTo(holeCF * CFrame.new(pos) * CFrame.Angles(0, math.rad(yaw), 0))`, using `placements` (hole-local; `holeCF = CFrame.new(world_offset) * CFrame.Angles(0, math.rad(world_yaw), 0)`).
5. **Moving parts**: weld every MeshPart of the model to the first one (or set PrimaryPart) and drive the model with `PivotTo` each Heartbeat, using the same formula as the collision blockers in holes.json: rotate → `pivotCF * CFrame.fromAxisAngle(axis, rad(speed*t + phase))`; slide → `pivotCF + axis * offset(t)` (ping-pong in `range`); swing (pendulum, pass 6) → `hingeCF * CFrame.fromAxisAngle(axis, rad(amplitude_deg * sin(2*pi*t/period_s + rad(phase))))`. Because the mesh origin is the pivot, the visual matches the invisible blockers exactly.
6. **Scaling/stretching**: rail-kit straights, `timber_deflector_board`, `drop_face_stone` and `water_surface` can be stretched along the run axis (Model scale or MeshPart.Size; see `scale` / `scale_z_to` in placements). Textures stretch with them, so for long rails repeat `rail_straight_4` every ~4 studs and only stretch the last piece slightly (the assembly previews do this).

### Textures in Roblox

Each `<prop>__<Material>` child is one MeshPart and uses **one** texture (or none). The FBX already carries the box-projected UVs and the embedded PNG; if the importer drops the image, upload `textures/<file>.png` and either:

- **SurfaceAppearance** (recommended): add a SurfaceAppearance to the MeshPart and set `ColorMap` to the image. Keep `MeshPart.Material` from the table (sound/physics) and keep `MeshPart.Color` as the flat fallback; or
- **MeshPart.TextureID** = the image (simplest; the texture replaces the colour).

Untextured materials (paper, glow, caps, water, iron, ink, ...) stay flat: just set Color/Material. Textures tile every `tile_studs` studs in prop space, so props keep the same texel density at any position; scaled instances scale the texture with them.

## Set dressing (per hole, world-placed, pass 4)

The pass-2 hole-local layouts (`_src/dressing_seed_pass2.json`) were re-validated in the **real world layout** (`../world/world.json` hole origins + yaw) by `_src/dressing_world.py`: every instance is transformed to world space, tested against every hole, walkway/stair/landing, lantern post, plaza, the mill flume and the world FBX geometry (hollow tree shell/roots/interior, waterfalls, cliff kits, rock faces, ...), grounded on `terrain-4stud.json`, then kept, nudged, converted to a card, or removed. Gaps were refilled.

**Import (preferred):** for each `manifest.json > dressing.holes.HN.instances[]` entry, clone `fbx/<prop>.fbx` and `Model:PivotTo(CFrame.new(world_pos) * CFrame.Angles(0, math.rad(world_yaw), 0))`, then `Model:ScaleTo(scale)`. `world_pos.y` is the base on the terrain (`terrain_y` = terrain height under the origin); hole-local `pos`/`yaw` give the same result through `holeRoot = CFrame.new(origin) * CFrame.Angles(0, math.rad(yaw_deg), 0)`. **Blockout alternative:** `fbx/dressing_hNN_*.fbx` are the same instances merged per material (repeated pieces merged into a few MeshParts). **Origin convention: hole frame**: place each file with `Model:PivotTo(holeRoot)`. `lights_world[]` (and hole-local `lights[]`) = lantern glow-core centres for PointLights (Range 8, Brightness 0.6 day / 1.6 night, #FFB347). H9's interior wall light spots are in `manifest.world.h9_interior_lights`.

### Quest VR budgets

- **Near field**: near-field tris of hole N = all dressing instances (any hole) whose origin lies within 60 studs of hole N's felt. Target well under 40k for Quest; enforced <= 34000.
- **Far field**: every pass-2 backdrop clump (tree_backdrop_cluster, 834 tris) is replaced by a card clump (treeline_card_red / _gold, 3 crossed quads, 12 tris); refill beyond the near field uses cards only (>= 40 studs from their own felt, >= 26 from any felt).
- **No LODs**: No separate LOD / far versions: Roblox auto-LODs MeshParts and streams nearby parts. Repeated pieces are merged per material in the fbx[] groups.
- Own share per hole (tris): lantern 5200, tree 7400, far 2600, ground 6500, interior 9000, accent 4000, hollow 6000, lantern8 4500; heavy small props (> 900 tris: toadstool clusters, glowing mushrooms) at most 2 per hole.
- World pieces are not part of these numbers (they are budgeted in the World pieces section).

**Clash rules** (checked by `fitcheck.py` on the re-imported FBX groups: exact triangle-vs-box test + world occupancy + grounding):

```
(every prop vertex, world space) against:
     - every hole: felt +1.25 up to felt top +6.5, collision walls, hazards, moving-part sweeps, teleports, tee pad +
       run-up, hero props (world_fit.hole_obbs);
     - every walkway / stair / landing segment: width/2 + 0.75, 6.5 high (12 at the Heartwood Door) and the 54 lantern
       posts (world_fit.path_obbs / lantern_obbs); plazas / viewpoints (POI radius) and the mill flume;
     - the world FBX geometry: tree shell, roots, interior, waterfalls, cliff kits, terrace rock faces, tower, dock,
       sister trees, tree line (world_occ: per-part height intervals on a 1-stud grid);
     - the hollow tree: non-H9 dressing may not come within the trunk's outer radius + 1; H9 dressing must stay
       inside the hollow (r < inner radius - 0.3).
footprint terrain spread <= 1.5 (small props, lantern poles), <= 3 (trees), <= 3.5 (cards); no water cells
```

## World pieces

Pass 3 adds world-scale background meshes for the continuous world in `../world/` (world.json, terrain, placements). They live in `models/world/`:

| Path | What |
|---|---|
| `world/fbx/<id>.fbx`, `world/fbx/<id>_partN.fbx` | One FBX per piece, or several parts that share one origin (every file < 20k tris) |
| `world/manifest.json` | Every piece: files, parts (role, tris, bbox, meshes/materials), origin, notes, **instances** (world pos / yaw / scale) |
| `world/layout.json` | Just the instances (written by `_src/world_layout.py`) |
| `world/previews/<id>_34.png` (+ `hollow_tree_world_shell_door/cutaway/top_fit.png`) | Piece previews |
| `world/previews/vista_*.png` | World vistas over a preview-only terrain mesh (holes as felt boxes) |
| `world/contact_sheet_world.png` | All previews + vistas |
| `world/fitcheck_world.txt` | Hero tree vs H8/H9/walkways fit check (`_src/world_fitcheck.py`) |

**Import (RobloxDevBot):**

1. File > Import 3D each FBX with the **scale unit Stud** (same as the props), keep the hierarchy: one Model per file, one MeshPart per material `<part>__<Material>`. Set Color/Material/Transparency from the material table above (new world materials are listed below). Anchored, `CanCollide = CanQuery = CanTouch = false` (all decoration).
2. **Positions are world studs** (+X east, +Y up, -Z north, the same frame as world.json and the placed holes), and they are the **base centre** of the piece (exceptions are in the `origin` column). Every part of a multi-part piece has the same origin, so put the parts in one Model and pivot the Model.
3. Place each instance with `Model:PivotTo(CFrame.new(pos[1], pos[2], pos[3]) * CFrame.Angles(0, math.rad(yaw), 0))`. ## Import scale note

The FBX header reports UnitScaleFactor 100 (metres): that is what Blender writes for unit system NONE + FBX_SCALE_UNITS.
The vertex values are already studs (a re-import into Blender gives 1:1 sizes). In Studio's Import 3D dialog,
**set the scale unit to Stud** (or check that `lantern_large` comes in 2 studs tall). If a prop comes in 3.57x too big,
the importer treated the file as metres: re-import with Stud, or scale the model by 0.28.

## Pass 2 notes (dressing + textures)

_Superseded in pass 4 where noted: dressing is now world-placed on terrain-4stud.json, checked against the real
walkway polylines, and budgeted for Quest (see "Set dressing" above and the pass 4 notes below)._

- **Dressing ground height**: `pos.y` comes from a preview-only stepped ground (nearest felt top - 0.6, under water
  surface - 0.5). Terrain in Studio will differ, so raycast each instance down onto Terrain (see the dressing section).
  Trees sink 0.1 and small props 0.04 into that ground, and the root flares reach 0.3 below their origin.
- **Neighbouring holes share space**: layouts are checked in world space against every hole, so each hole's dressing
  never touches another hole's felt, rails or walking path. The holes are packed closely (H4/H5/H6/H7), so H6 has
  few trees of its own. Its tee view is framed by H4/H5/H7 dressing, and the previews draw neighbours' dressing too
  (snapped onto the previewed hole's ground).
- **Walking paths** are modelled as straight 5-stud corridors from each cup to the next tee. If the real paths
  curve, re-run `dressing.py` after adding them to `dressing_lib.build_keepouts`.
- **Overhead clearance** is 6.5 studs above any felt or path (lantern spans, overhanging maples). That is enough for
  a 5-stud VR player plus a raised putter. Raise `dressing_lib.CLEAR` if playtests show people hitting lanterns.
- **Triangles**: dressing runs 80k-200k tris per hole. Imported as instances, it renders as a few dozen unique meshes.
  The merged `dressing_hNN_*` groups don't instance, so prefer instances in production. They also cull worse.
- **Textures**: box projection leaves visible seams on curved shapes, such as where a texture changes axis on a trunk.
  At these texel sizes that's acceptable for a stylised look. Foliage is a 2D leaf pattern, not leaf cards, so canopies
  stay chunky low-poly blobs.
- **Preview look** (golden-hour sun, haze, glare) comes from the Blender renders. Match it in Studio with the

- **World placement**: dressing positions come from `dressing_world.py` (world.json placements), not holes.json
  `world_offset`. Ground heights are bilinear samples of `../world/terrain-4stud.json`. If Studio Terrain is built
  differently (smoothing, the felt Air carve), raycast down from `world_pos + (0, 20, 0)`.
- **Budget first**: the near field of the packed holes (H5-H8 sit within 11-60 studs of each other) is shared, so
  those holes keep fewer trees of their own. Their views are framed by the world pieces (tree roots, cliff kits,
  falls), neighbours' dressing and card treelines. Raise `NEAR_BUDGET` in `dressing_world.py` if Quest profiling
  allows it.
- **Cards**: `treeline_card_red/_gold` need an alpha-cut texture in Studio (SurfaceAppearance AlphaMode =
  Transparency, or MeshPart.TextureID). Their back faces are real geometry, so DoubleSided is not needed. Set CastShadow off.
- **Felt** (`textures/felt.png` + `felt_normal.png`): softer and slightly darker, with a faint nap running along
  each felt piece's long axis. Use a SurfaceAppearance with ColorMap = felt.png and NormalMap = felt_normal.png on
  Fabric so slopes catch the light.
- **H9 interior**: `hollow_tree_world_shell_part8.fbx` adds 18 low lantern clusters and 24 glowing mushroom clumps
  along the inner wall. Add PointLights at `manifest.world.h9_interior_lights` (30 spots; Range/Brightness in the note).
  H9 dressing adds floor-level glowing mushrooms, ferns and toadstools inside the ring.
- **Previews**: `assembly_world.py` renders over a preview-only terrain mesh with 4-stud cells, so slopes look
  faceted and water cells look stepped. Studio Terrain will be smooth.

## Pass 5 notes (playtest review: dark holes, lane clutter, moving-part colours)

- **Dark holes H8/H9**: use `hole_skins` (above). The felt Parts get `FeltBright` (`#6CBF4C`, Fabric,
  SurfaceAppearance ColorMap = `textures/felt_bright.png`, NormalMap = `felt_normal.png`), and the rails use the
  `rail_*_trim` kit (light stone + cream cap) so the lane edge separates from the bark floor. Add the
  `spot_lights[]` PointLights (pooling over the H8 door, H9 gate, H9 lantern bar and both cups) and a PointLight on
  each `cup_lantern_stake` Neon core (Range 10, Brightness 2, `#FFC873`).
- **H6**: `rail_*_mill` kit (dark blue-grey MillSlate blocks + painted MillBlue cap), so the mill hole reads as a
  different place from H5/H7.
- **Moving parts**: MoveRed/MoveCream bands. If Studio lighting makes the cream glare, drop MoveCream to `#F2E4C4`.
  Keep both colours off static props, so red-and-cream always means "this moves".
- **Lane clearance**: no dressing prop taller than 2 studs within 3 studs of any rail (footprint, and everything below
  eye height). When hand-placing extra props in Studio, keep to the same rule; short ground cover (grass, ferns, small
  bushes, the cup lantern stakes) may still sit by the rails.
